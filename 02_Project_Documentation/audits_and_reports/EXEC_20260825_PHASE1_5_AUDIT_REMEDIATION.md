## 1. 已完成的修复

### P0：主线与状态持久化

- 修复纪元跃迁选择逻辑。文化值一次跨过多个阈值时，纪元推进会从当前状态向上寻找已满足门控的最高纪元，不再因直接命中尚未满足的星屑门控而永久停在危机纪元。
- 将“人物已解锁”和“当前空闲可任命”拆为 `PersonManager.unlockedPersons` 与 `availablePersons`。AI 任命部长后，丁仪、杨冬等仍保留剧情资格；死亡状态仍会阻止后续人物事件。
- 事件 Flag 延迟到玩家确认/选择后提交；`grantsFlags` 已贯通事件数据解析、固定事件、filtered 事件和恢复后的待处理事件。
- `currentEvent`、`eventQueue`、事件选择的 `effects/flags` 和 continuation 纳入存档；读取后重建可执行 action，避免“事件已触发但选择消失”。
- 反序列化改为重建带私有字段的核心对象，并重新注入 `Game`；恢复 Tag、生态链、关系网络、氛围、历史生成器和切片叙事模块。
- 回溯恢复待处理事件，并保留回溯后的对象图继续运行所需的引用和子系统状态。

### P1：人物、结局和高风险固定事件

- 丁仪自杀随机事件和杨冬死亡路径写入人物死亡状态及 canonical death Flag；固定、filtered、random 事件统一检查真实人物表、解锁状态、存活状态和纪元死亡表。
- 死亡对账清理执剑人实体、面壁者关系和 `swordholder_appointed`；交接 Flag、人物实体和旧存档兼容路径统一通过 `syncSwordholderState()` 收敛。
- 黑域固定事件增加科技门控和未解决门控；接受/拒绝分支写入互斥的 resolved/rejected 状态，归零者和小宇宙固定事件不再覆盖玩家此前的拒绝选择。
- 结局页面解析 `neutralType`，中性结局不再被当作失败结局展示。

### P2/P3：反馈链和玩家入口

- 结局预报在完整条件未成立时最高显示 99%，只有实际 `check()` 成立才显示 100%。
- 生态链只在事件真正结算后激活；延迟完成时按 `resultEventId` 直接进入同一事件队列，并记录历史，不再重新随机抽取无关事件。
- 多槽位存档入口已接入设置页，支持 `autosave/slot1/slot2/slot3` 的保存、读取、删除和元数据展示。
- 追加了跨系统回归场景，覆盖首个纪元跃迁、人物死亡过滤、待处理事件存档、对象图恢复、生态链结果 ID、结局进度防假阳性、黑域门控和多槽位入口。

## 3. 仍不能宣称 VERIFIED 的项目

- 通用 first-choice reachability 在本次 1×220 矩阵中没有自然触发正面结局；这证明主线入口已恢复，但不证明所有正面/隐藏结局的玩家路径均可达。该项继续标记为 `TEST-GAP / CLAIMED-BUT-UNVERIFIED`，不能用“模拟未崩溃”替代。
- Playwright Chromium 本次未形成有效 UI 证据：44 个用例中需要浏览器的用例在启动前因环境缺少 Chromium 可执行文件失败；尝试下载时 CDN 返回截断的 0 MiB 压缩包。2 个纯断点函数用例通过，3 个既有 skip 保持不变。该结果是验证环境阻塞，不应解读为 UI 断言已通过。
- 科技 → 事件条件 → Flag → 结局的完整无状态玩家路径，以及中途存档后继续到正面结局，仍需专门的真实玩家路径测试；本次没有伪造这类证据。

## 4. 用户反馈对应结论

“事件已经显示进入新纪元，但状态栏仍是危机纪元”的根因是纪元门控和人物资格的组合断点：AI 任命会从 `availablePersons` 移除丁仪等人物，导致关键事件被错误过滤；同时文化值过高时 `updateEpoch()` 可能直接命中尚未满足的更晚纪元。两处均已修复。

丁仪讣告后仍出现丁仪事件、杨冬死亡后仍出现杨冬事件的根因是事件池曾使用不完整的静态人物名单，且死亡叙事未统一写回 `isAlive`。现在事件资格使用完整人物表和 `isAlive`，死亡事件写入 canonical Flag；历史/录像/档案文本仍可作为回放显示，不被误判为当前人物发言。

## 5. 结论

本次已完成审计报告中 P0 主线、存档/回溯、人物死亡过滤、P1 固定事件、P2 生态/结局进度和 P3 多槽位入口的代码修复，并用生产入口回归验证首个纪元闭环。核心系统不再维持原报告中确认的首个主线卡死状态；正面结局全路径和浏览器 UI 仍按证据边界保留为后续测试缺口。
