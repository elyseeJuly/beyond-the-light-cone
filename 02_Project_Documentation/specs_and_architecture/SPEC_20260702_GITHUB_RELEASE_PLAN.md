# GitHub Release 及版本控制计划规范

## 1. 概述
本规范旨在标准化《光锥之外：纪元往事》（Beyond the Light Cone）的版本迭代、GitHub Release 发布流程以及变更日志（CHANGELOG）的撰写标准，确保项目的每次更新都有迹可循，便于玩家了解版本变化以及开发者进行历史回溯。

## 2. 版本号命名规范 (Semantic Versioning)
本项目严格遵循 [语义化版本 2.0.0](https://semver.org/lang/zh-CN/) (SemVer) 规范。
版本号格式为：`v主版本号.次版本号.修订号[-先行版本号]` (例如 `v1.0.0`, `v0.9.1-beta.1`)。

*   **主版本号 (Major)**：发生不兼容的 API 修改或重大的核心玩法变更时增加（例如：全新大版本发布、重构底层机制）。
*   **次版本号 (Minor)**：向下兼容的功能性新增或显著体验优化时增加（例如：新增游戏事件、结局、新系统模块）。
*   **修订号 (Patch)**：向下兼容的问题修正（Bug 修复、文案调整、小的平衡性修改）。
*   **先行版本号 (Pre-release)**：用于正式发布前的测试阶段（例如：`alpha`、`beta`、`rc`）。

## 3. GitHub Release 发布流程
所有正式和测试版本的发布，必须通过 GitHub Release 进行管理。

### 3.1 发布前准备
1.  **代码冻结与测试**：完成目标版本的所有开发工作，并在本地或自动化测试环境中通过所有测试用例。
2.  **更新 CHANGELOG（发布文档）**：**每次更新版本，必须在项目根目录的 `CHANGELOG.md` 中添加对应的发布更新说明。** 更新内容需按照规定的格式分类列出。
3.  **提交并打 Tag**：将 `CHANGELOG.md` 及其他配置文件的修改提交到 `main` 分支。并在该提交上打上对应的版本 Tag（例如 `git tag v1.0.0`），然后推送到远程仓库（`git push origin v1.0.0`）。

### 3.2 创建 GitHub Release
1.  在 GitHub 仓库的 Releases 页面点击 "Draft a new release"。
2.  **Tag 选择**：选择刚刚推送的对应版本 Tag（如 `v1.0.0`）。
3.  **Release 标题**：格式通常为 `Release v主.次.修 [- 先行版本号]`，亦可增加简短的版本代号或核心更新概括（例如 `Release v1.0.0 - 星海纪元`）。
4.  **Release 说明（Description）**：将 `CHANGELOG.md` 中对应版本的更新说明完整复制到此处，作为 Release 的发布文档主体。
5.  **Release 资产（Assets）**：
    *   如果有打包好的客户端文件（如 Windows 的压缩包），应作为资产附件手动上传。
    *   对于 Web 端，因为是自动部署到 GitHub Pages，请在说明中附上线上游玩链接。
6.  **发布类型**：如果是测试版，勾选 "Set as a pre-release"；如果是正式版，且是当前最新稳定版，确保它是 "Latest release"。

## 4. CHANGELOG 撰写规范
项目根目录下的 `CHANGELOG.md` 承担了“核心发布文档”的作用，用于记录所有版本的更新说明。

### 4.1 格式要求
每次发布新版本，必须在文档顶部添加新的版本记录，标准格式如下：

```markdown
## [vX.Y.Z] - YYYY-MM-DD

这里是一段简短的版本概述，说明本次更新的核心目的（如：引入了XX新机制，修复了影响游戏进程的严重 Bug 等）。

### 新增 (Added)
- 新功能、新玩法、新事件、新结局等。

### 优化 (Optimized / Changed)
- 对现有机制的修改、数值平衡调整、UI/UX 改进、性能提升等。

### 修复 (Fixed)
- 修复的各类 Bug 和已知问题。

### 移除 (Removed)
- 废弃或删除的过时功能及机制。
```

### 4.2 撰写原则
*   **面向玩家为主**：尽量使用玩家易懂的游戏内术语，而非晦涩的技术术语（除非是针对开发者的纯技术侧更新）。
*   **分类清晰**：严格按照 `新增`、`优化`、`修复`、`移除` 等类别进行归类，没有变更内容的分类标题应当省略。
*   **颗粒度适中**：无需记录代码级别的微小重构（除非显著提升性能或解决了特定崩溃），重点记录玩家可感知的内容变更和核心逻辑修复。
